## Recording commands

After starting the website, record a real selected analysis:

```bash
uv run python scripts/record_demo.py --run-id REAL_RUN_UUID --require-llm --output output/video/flooline-script-demo.mp4
```

For an explicitly synthetic walkthrough, add --preview and use a current-route demo UUID. The helper uses an isolated Chromium profile and ffmpeg, records captions without voiceover, retains engine/mode labels and exports a three-minute MP4 plus a manifest. Each scene is edited to its fixed playback cue, preserving the narration timing and final attribution. The --require-llm flag rejects supported answers that fall back instead of using Groq. A take is also rejected for visible UI errors, HTTP errors, JavaScript page errors or new acquisition requests. Do not use victim imagery.

## Judge Q&A prompts

- Where do measurements come from? Saved raster/vector and road-network results, resolved by Python rather than generated by the model.
- What happens if Groq is unavailable? A labeled evidence-backed deterministic fallback.
- Is a building confirmed destroyed? No; intersection means potential exposure.
- Is a village physically inaccessible? The system reports modeled connectivity under assumptions, not verified closure.
- Why is a date unavailable? The selected run did not record it; the system does not infer it from a scene identifier.
- Does this need Kuro Siwo or Sen1Floods11? No; this selected AI component is the Copilot, and it reads computed mapping results.
- Does this prove real-event accuracy? No. The saved run has partial observations and the class-matched EMSR927 comparison is N/A; the video demonstrates the interface and numerical grounding only.
